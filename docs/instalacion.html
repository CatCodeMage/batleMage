Guía de instalación

Fase presentable 0 · Juego 3D en OpenGL · Equipo de 6 personas · Última actualización: 2026-09-30

Pendiente: enunciado del proyecto, reparto de tareas y arquitectura del código. No afectan a la instalación.

Requisitos

  • Windows 10/11 de 64 bits.
  • Visual Studio con la carga de trabajo Desarrollo para el escritorio con C++.
  • Driver de la tarjeta gráfica actualizado (aporta la implementación real de OpenGL).
  • Git.

Clonar y ejecutar

  1. Clonar el repositorio: https://github.com/CatCodeMage/batleMage.git
  2. Abrir posibleProyecto.slnx con Visual Studio.
  3. Elegir x64 y Debug en la barra superior.
  4. Ejecutar. Debe salir una ventana azul oscuro y una consola con la línea OpenGL: ....
¿Hay que descargar algo más? No. Las librerías están dentro del repositorio, en posibleProyecto\libs, y el proyecto las busca con rutas relativas ($(ProjectDir)libs\...), así que funciona igual en cualquier ordenador y carpeta.
¿Por qué el proyecto es "vacío"? La plantilla de Proyecto vacío (C++) no trae código que haya que borrar ni depende de MFC o ATL, que son para interfaces clásicas de Windows y COM. Un juego OpenGL crea su propia ventana con una librería. Las plantillas DLL y biblioteca estática generan bibliotecas, no un ejecutable, y la de Makefile usa un sistema de compilación propio que no necesitamos.

Configuración del proyecto (Debug|x64 y Release|x64)

Ya está guardada en el .vcxproj. Se documenta para saber qué hace cada ajuste y poder revisarla.

Solo Release: Vinculador → Sistema → SubsistemaWindows (/SUBSYSTEM:WINDOWS)
Solo Release: Vinculador → Opciones avanzadas → Punto de entradamainCRTStartup
¿Por qué GLEW estático (glew32s.lib + GLEW_STATIC)? La versión dinámica (glew32.lib) exige copiar glew32.dll junto al .exe, que se genera en x64\Debug, una carpeta ignorada por Git. Cada compañero vería el error "no se encontró glew32.dll". Enlazando GLEW de forma estática el código va dentro del .exe y no hay DLL que copiar. GLFW y SOIL2 ya son estáticas.
¿Por qué la terminal solo en Debug? En Release el subsistema es Windows, y mainCRTStartup hace que siga arrancando en main() sin cambiar el código. Consecuencia: en Release no se ve std::cout ni std::cerr, así que los errores se depuran siempre en Debug.

Problemas frecuentes

SíntomaCausa probable
C1083: no se puede abrir el archivo incluir 'X'Falta la ruta de inclusión o está en la configuración equivocada (Debug y Release se configuran por separado).
LNK2019: símbolo externo sin resolverFalta una .lib en las dependencias, falta su ruta de biblioteca, o se compila en x86 en lugar de x64.
"No se encontró glew32.dll"Falta GLEW_STATIC en el preprocesador o se enlaza glew32.lib en lugar de glew32s.lib.
LNK4098 (LIBCMT en conflicto)Aviso, no error. Ver la guía técnica.
Los cambios en Propiedades no se guardanHay que pulsar Aplicar y Aceptar, y guardar con Ctrl+Shift+S.
