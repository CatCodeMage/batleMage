Arquitectura

Pendiente. Ahora mismo todo vive en main.cpp (ventana azul con el bucle de juego). Aquí irá la estructura de carpetas y clases (quién es responsable de qué) cuando la definamos.

Bucle de juego

Estructura de cualquier juego, independiente de la librería. Es lo que hace el main.cpp actual:

inicializar GLFW y crear ventana (contexto OpenGL 3.3 core)
inicializar GLEW (después de tener el contexto)
mientras la ventana esté abierta:
    procesar entrada (glfwPollEvents)
    actualizar lógica (dt = tiempo desde el último frame)
    dibujar (limpiar pantalla, renderizar, glfwSwapBuffers)
liberar recursos (glfwTerminate)
¿Por qué GLEW va antes que GLFW en los #include? GLEW redefine partes de gl.h. Si se invierte el orden, da error de compilación.
¿Por qué glewExperimental = GL_TRUE? Con perfil core, GLEW falla al cargar algunas funciones si no se activa.
¿Por qué usar dt? Para que la velocidad del juego no dependa de los FPS del ordenador de cada uno.

Notas técnicas

Aviso LNK4098 (LIBCMT)

Aparece al enlazar: "la biblioteca predeterminada 'LIBCMT' entra en conflicto con otras bibliotecas". Es un aviso, no un error.

  • El programa necesita una biblioteca con las funciones básicas de C (printf, malloc...). Es el CRT, y existen dos modos: estático (/MT, LIBCMT) y dinámico (/MD, MSVCRT).
  • El proyecto usa el dinámico, pero alguna .lib estática enlazada (glfw3.lib, glew32s.lib o soil2.lib) se compiló con el estático. No hemos comprobado cuál lo provoca.
  • Riesgo: fallos raros si un objeto se reserva en un CRT y se libera en otro. Por ahora es inocuo.
  • Posible solución: añadir LIBCMT en Vinculador → Entrada → Omitir bibliotecas predeterminadas específicas (lo hace el proyecto base del profe). Pendiente de decidir.

Debug y Release

En Release no hay consola (subsistema Windows), así que std::cout no se ve. Las dos configuraciones se configuran por separado en Visual Studio; hay que repetir los cambios en ambas, salvo las definiciones del preprocesador, que son distintas a propósito (_DEBUG / NDEBUG).

Git

  • El .gitignore parte de la plantilla de Visual Studio, que ignora bin/, Release/ y x64/.
  • Esas reglas excluían por error glew32.lib y glew32.dll de libs, que están en carpetas con esos nombres. Se corrigió al final del fichero con !**/libs/ y !**/libs/**, que hacen una excepción para libs.
  • libs pesa unos 43 MB (GLM 21, GLEW 11, GLFW 11, más SOIL2). Mucho es documentación y carpetas de librería para otras versiones de Visual Studio que no usamos; se podría adelgazar más adelante.
  • Comprobar qué ignora Git: git check-ignore -v <ruta>.

Preguntas que puede hacer el profe

Añadid aquí más preguntas con su respuesta corta, para repasar en grupo.

  • ¿Qué es OpenGL? Una API gráfica multiplataforma para comunicarse con la GPU. No crea ventanas ni lee teclado: para eso se usa una librería auxiliar.
  • ¿Por qué necesitamos GLFW además de OpenGL? OpenGL solo dibuja. Crear la ventana, el contexto y leer la entrada depende del sistema operativo, y GLFW lo resuelve.
  • ¿Por qué necesitamos GLEW? Windows solo expone directamente OpenGL 1.1. Para las funciones modernas (shaders, VAO) hay que pedirlas al driver en ejecución, y GLEW lo hace por nosotros.
  • ¿Qué diferencia hay entre una librería estática y una dinámica? Ver el glosario.
  • ¿Por qué ese aviso de LIBCMT? Ver las notas técnicas.
  • ¿Por qué no usáis el entorno del profe entero? Preferimos montar el nuestro para entender cada pieza, y reutilizamos solo SOIL2, que sí nos hacía falta para texturas.
  • ¿Por qué un proyecto vacío? Ver la guía de instalación.
